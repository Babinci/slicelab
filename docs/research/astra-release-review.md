## Focused source review

- **Canonical input:** `canonicalSeparationInput` writes immutable JUCE-decoded stereo PCM as float32 WAV in bounded background chunks, rereads and bit-compares every sample, hashes the finished file, and atomically renames it. This preserves MP3 timeline padding and over-unity samples. Non-WAV and multichannel WAV sources take this path; readable mono/stereo WAV preserves its old transport identity.
- **Manifest binding:** `bindSeparationManifest` requires the returned transport hash, rate, stereo channel count, and exact frame count before recording both transport and original source identities. `readStemFiles` then checks every stem checksum, length, rate, and finite sample. Original-source checks run before/after the worker, and generation checks prevent a stale result replacing a later source. No new binding defect was found. The real MP3 timing result remains a timeline test, not a quality score.
- **Markers:** import bounds input at 256 KiB, rejects embedded NUL/invalid UTF-8, strictly parses two CSV/TSV fields, requires finite distinct in-range times, and rejects source-frame collisions after rounding. All validation and capacity checks precede one undoable mutation. Favorites and immutable source ownership survive; generation/source identity are rechecked under the session mutex. Generic text interchange is correctly distinguished from native Serato DJ metadata.
- **Metronome:** the click follows the audible logical source cursor and piecewise beat map, rather than Rubber Band's ahead-of-output input cursor. It uses fixed voice fields, runs only on source preview, is master-gain-scaled, and resets on preview start/stop or disabling. It does not add callback heap ownership or pad/export clicks. Direct/scheduled timing and pad independence have dedicated tests.
- **Legacy parameter migration:** the new `metronome` parameter is appended after existing parameters. Restore adds its default-off child only when exactly one parameter is missing and that child is metronome; count, known-ID, uniqueness, and range validation still runs. The new `legacyStateTests` constructs exactly 410 original parameters, starts with METRO on, checks default-off migration while preserving nondefault source/pad/control/beat-map state, then rejects duplicate and out-of-range corruptions without clobbering the session. The refreshed 30-check runtime artifact passes these three added assertions, closing the missing-fixture flag.
- **Dropdown synchronization:** three model-ID caches begin at -1; `UI::refresh` now writes source key, target key, and grid interval only when their model value changes. A timer refresh therefore leaves a pending user selection intact until its asynchronous callback commits it. Existing callback gesture and model-update paths remain intact. No concrete defect found in the minimal fix; actual host retest remains distinct from source review and pluginval.
- **Prior state/lifetime paths:** local promise ownership is released before restore waits; erased/throwing jobs can therefore ready the future on destruction. Hazard scans follow call → request → acquiring/retained → voice handoffs. ASan/UBSan and corrected TSan publication stress support the lifetime implementation within their sampled schedules.
- **Packaging/privacy:** corresponding source is assembled from tracked `git archive HEAD` content for the root, APC, JUCE, and Rubber Band repositories, rather than copying ignored working directories. The inspected root contains 73 UTF-8 regular files and two vendor gitlinks, with no development media/weight/binary filenames or private-key headers; targeted current-doc secret-pattern checks found no credential text. This limited source scan does not replace the final staged and actual-package scan. The package also copies the docs directory from the working tree, so that directory must remain part of the final scan. No new concrete packaging defect was identified.
- **MIDI fix review:** regression asserts exact note/channel/velocity/tick data, a single end-of-track event, replacement by a shorter file, empty export, and permission-failure preservation. Pinned `MidiFile::readFrom` checks that no bytes remain. The planned `File::replaceWithData` helper was rejected because it ignores append failure, and JUCE replacement may fall back to copying. The actual patch checks a sibling temporary write, flush status and closed-file size, then uses `std::rename`; failed writes never reach rename and no copy fallback is used. It clears the prior export error on success. Red/green and GUI overwrite artifacts now close the identified defect. The permission test proves that tested failure path; storage exhaustion was source-reviewed rather than fault-injected.
